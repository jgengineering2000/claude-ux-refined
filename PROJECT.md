# AUR — AI UX Refinements

## Vision

Most AI coding assistants are used through a narrow side panel with default layouts,
generic status text, and no structured way to capture or navigate the documents they
produce. AUR provides the layer between the raw AI tool and a productive daily workflow:
tighter UI, a prompt library, and a local document infrastructure that makes AI output
reviewable, annotatable, and version-controllable.

## Goals

- **Reduce friction** in the Claude Code interface — less wasted space, less visual noise.
- **Standardise prompt patterns** so recurring workflows (audits, releases, debug sessions)
  produce consistent, navigable documents rather than ephemeral chat text.
- **Make AI output durable** — HTML documents with annotation, timestamped, stored
  alongside the code they describe, readable by the AI in future sessions.
- **Work with any project** — nothing in AUR is domain-specific; it adapts to any
  codebase or workflow.

## Non-Goals

- Not a Claude Code fork or wrapper — AUR patches only what the user owns (extension
  assets in their home directory, local config files).
- Not a document editor — HTML output is generated by Claude; AUR provides the
  infrastructure to store, serve, and annotate it.
- Not a cloud service — everything runs locally; no telemetry, no accounts.

## Principles

1. **No sudo unless unavoidable.** The system-browser patch is the only exception;
   user-local IDE installs never need elevation.
2. **Safe to re-run.** Every patch and installer step detects already-applied state
   and skips or reports rather than double-applying.
3. **No lock-in.** All formats are plain text (HTML, JSON, Markdown). Annotations are
   plain JSON. Removing AUR leaves no residue beyond the patched extension files
   (which carry `.bak` originals).
4. **Prompt-first.** The quick-prompt bar and PROMPTS.md are the primary user-facing
   feature; the patches are quality-of-life improvements that support it.

## Components

| Component | Path | Purpose |
|---|---|---|
| IDE patches | `patches/` | Modify Claude Code extension assets in-place |
| Doc server | `server/server.py` | Serve HTML docs + annotation API |
| Manifest | `server/manifest-link.js` + `templates/manifest.html` | Document hub |
| CLAUDE.md template | `templates/CLAUDE.md.template` | Project-level Claude instructions |
| Installer | `install.py` | Interactive setup for all components |
| Prompt spec | `PROMPTS.md` | Canonical prompt library |

## Roadmap

### Current — v1.x

- Chat panel layout patch (A1)
- Processing vocabulary patch (A2)
- Simple Browser tab title patch (A3)
- Doc server with annotation API
- Manifest hub with quick-prompt bar
- Interactive installer
- PROMPTS.md prompt library

### Near-term

- Screenshot and demo assets for GitHub promotion
- Per-project prompt overrides (project-level `PROMPTS.md` merged with global)
- Installer: auto-detect user-local vs system IDE install, remove sudo prompt when
  not needed

### Longer-term

- Patch update checker (detect when a Claude Code update breaks a patch)
- Manifest search and filtering
- Annotation export (JSON → Markdown summary)
